# hardware-modules/strobe-imaging/strobe_pic/ — Strobe Imaging PIC firmware

Firmware for the Strobe Imaging module’s PIC. The host (Raspberry Pi) talks to this firmware over SPI to enable/disable the strobe, configure timing, and read back camera read-time. The host-side counterpart is `software/drivers/strobe.py` (used via `software/controllers/strobe_cam.py`).

## What’s in this folder

- **Application logic**: `main.c`
- **SPI framing / transport**: `spi.c`, `spi.h`
- **Shared definitions**: `common.h`
- **Generated peripheral code**: `mcc_generated_files/` (generated by Microchip Code Configurator; hand-merged in `interrupt_manager.c` and `tmr1.c`)
- **Superseded drafts, not compiled**: `main_hardware_trigger.c`,
  `interrupt_manager_hardware_trigger.c`. These drive the strobe from the TMR1
  gate interrupt, which does not work on this board — see
  [`FLASH_HARDWARE_TRIGGER.md`](FLASH_HARDWARE_TRIGGER.md). Do not flash them.

Generated/build artifacts often present locally (not tracked in git):

- `build/`, `dist/`: MPLAB outputs (e.g. production `.hex`). Always
  **Clean and Build** before programming — a stale `dist/.../*.hex` was once
  committed and caused a v1 reflash by mistake.

## SPI interface (host protocol)

### Packet framing

SPI packets are framed as:

- `[STX=2][size][packet_type][data...][checksum]`
- checksum is chosen so that the sum of all bytes modulo 256 equals 0

See `spi.c` (e.g., `spi_packet_read()` and related helpers).

### Packet types (source of truth: `main.c`)

`main.c` defines packet types and payload interpretation:

- `1` — **SET_STROBE_ENABLE**
- `2` — **SET_STROBE_TIMING**
- `3` — **SET_STROBE_HOLD**
- `4` — **GET_CAM_READ_TIME**
- `5` — **SET_TRIGGER_MODE** (0=software free-run, 1=hardware, camera LineOut → RC5)
- `6` — **GET_DIAG** (firmware version, RC5 level, edge/flash counters, state)
- `7` — **SELF_TEST** (5 LED blinks of 250 ms; verifies the LED path over SPI)

For Daheng hybrid frame sync, flash this firmware and follow
[`FLASH_HARDWARE_TRIGGER.md`](FLASH_HARDWARE_TRIGGER.md).

## Compatibility notes

- Software free-run (trigger_mode=0): the firmware flashes continuously while
  enable=1, pacing wait and flash in software. Both are clamped to 65535 µs, so
  wait and flash of ~60 ms give a visible ~8 Hz blink; the default sub-millisecond
  values look like a steady light.
- Hardware trigger (trigger_mode=1): one flash per falling edge on **RC5** (the
  input is active low). The host must set Daheng LineOut=ExposureActive.
- `main.c` + `mcc_generated_files/interrupt_manager.c` are what MPLAB builds; the
  `*_hardware_trigger.c` drafts are excluded from `nbproject/configurations.xml`.
- `GET_CAM_READ_TIME` reports the camera readout gap, measured by TMR1 while the
  trigger line is high. It saturates at 65535 µs.

## Hybrid Daheng (CoolerMaster) + strobe (Pi)

Wire Daheng opto LineOut (ExposureActive, default Line2 / `RIO_DAHENG_STROBE_LINE`)
to the strobe board trigger input, which lands on **PIC RC5**. The host enables
sync via `/api/control/strobe/trigger_mode`.

Probe on the Pi (API stopped, SPI is exclusive):

```bash
cd ~/rio-controller
PYTHONPATH=. RIO_SIMULATION=false ./scripts/probe_strobe_trigger_mode.sh
PYTHONPATH=. RIO_SIMULATION=false python3 scripts/probe_strobe_diag.py --self-test
PYTHONPATH=. RIO_SIMULATION=false python3 scripts/probe_strobe_diag.py --seconds 30
```
